# Frontend Task 11 — Public Landing Page and Demo Entry

## Goal

Build the App Doctor public landing page from the approved landing-page plan and direct its sign-in/start-scan actions to the protected local demo entry.

## Implementation

- Build header, hero, illustrative product preview, clarity strip, workflow, capabilities, security statement, CTA, and footer.
- Use the shared deep-navy, slate, and teal system established by the landing page across public and authenticated surfaces.
- Route `Sign in` and demo `Start a health scan` actions to `/demo`, never to a fake account screen.
- Use a purpose-built HTML product preview; do not use stock imagery, invented customer logos, or generic AI art.

## Mandatory cross-check before Frontend Task 12

Test CTA destinations, keyboard navigation, mobile header, reduced-motion behaviour, and the public-to-demo route. Confirm the landing page makes no bug-free or root-cause promise.
