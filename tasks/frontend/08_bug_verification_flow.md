# Frontend Task 08 — Issue Intake Linked to Evidence

## Goal

Capture a real reported issue alongside the scan evidence without promising automated verification yet.

## Implementation

- Build issue intake: title, expected behaviour, actual behaviour, prerequisites, and linked run/result.
- Build issue list/detail and status updates.
- Explain that an issue is a report and evidence record; it is not an automatic root-cause diagnosis or verified-fix claim.
- Provide accessible edit/retry/error states.

## Local acceptance criteria

- A user can create and view a real issue linked to a scan result.
- Inconclusive evidence is distinct from a confirmed defect.

## Mandatory cross-check before Frontend Task 09

Create issues from each fixture outcome, test required-field/API-error states, keyboard traversal, and evidence links. Confirm language never overstates the result. Do not begin Task 09 until all checks pass.
